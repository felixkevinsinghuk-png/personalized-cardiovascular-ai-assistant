# 1. Project Summary

## What This Application Does
A locally deployed web application that takes a retinal fundus image as input
and outputs a cardiovascular risk assessment with visual explanations and
a natural language report generated by a local medical AI model.

## Core User Journey
1. User opens the app in a browser at localhost:5000
2. User uploads a retinal fundus image
3. App runs the image through two deep learning models
4. App fuses both model outputs into one risk score
5. App generates a Grad-CAM heatmap showing which retinal regions mattered
6. App passes all results to a local medical LLM to generate a written report
7. User sees the risk level, heatmap, and written explanation on the results page
8. User can ask follow-up questions via a chatbot on the same page
9. All results are saved to a local MySQL database for history review

## What Makes This Different
- Fully local — no internet required after setup
- No paid APIs or cloud services
- Three layers of explainability — visual, quantitative, linguistic
- Two CNN models working together via a fusion mechanism
- Safety-constrained LLM outputs with mandatory research disclaimers

# 3. Full 3-Layer Application Architecture

## Layer 1 — Web Layer (Flask)

Purpose: Receives user input, coordinates all components, returns results to browser.

How it works:
- User visits the home page and sees an image upload form
- On form submit, Flask receives the image file and saves it to static/uploads/
- Flask calls the ML pipeline and waits for results
- Flask saves all results to MySQL
- Flask redirects the user to the results page
- The results page fetches the saved prediction from MySQL and displays it

Pages needed:
- Home page: image upload form and research disclaimer
- Results page: risk score, heatmap image, LLM report, chatbot input
- History page: table of all past predictions pulled from MySQL
- Chatbot: real-time Q&A powered by local LLM via JavaScript fetch calls

## Layer 2 — ML Pipeline

Purpose: Takes the uploaded image and produces DR grade, CVD score, fused risk, and heatmap.

Step 1 — Preprocessing
- The image is loaded and black circular borders are removed using OpenCV
- The image is resized to 224x224 pixels
- Pixel values are normalised using ImageNet mean and standard deviation
- The image is converted to a PyTorch tensor ready for model input

Step 2a — ResNet-50 (DR Grading)
- The preprocessed tensor is passed through the trained ResNet-50 model
- The model outputs a probability score for each of 5 DR grades (0 to 4)
- The grade with the highest probability is selected as the prediction
- The grade and its label (Normal, Mild, Moderate, Severe, Proliferative) are saved

Step 2b — EfficientNet-B4 (CVD Risk)
- The same preprocessed tensor is passed through the trained EfficientNet-B4 model
- The model outputs a single score between 0.0 and 1.0
- Higher scores indicate greater CVD risk based on retinal hypertension markers

Step 3 — Weighted Fusion
- The DR grade is normalised to a 0 to 1 scale by dividing by 4
- Fusion formula: CVD_Score = (w1 x DR) + (w2 x CVD)
- Default weights: w1 = 0.4, w2 = 0.6
- Final score maps to: Low under 0.33, Moderate 0.33 to 0.67, High above 0.67

Step 4 — Grad-CAM Heatmap
- The grad-cam library hooks into the final convolutional layer of each model
- Gradients flowing back from the prediction are used to weight feature maps
- A low-resolution activation map is generated and resized to the original image size
- The activation map is overlaid on the original image as a colour heatmap
- Red areas = high activation (important regions), Blue areas = low activation
- The heatmap image is saved to static/heatmaps/ for display on the results page

## Layer 3 — LLM Layer

Purpose: Translates numerical model outputs into human-readable cardiovascular explanation.

How it works:
- A structured prompt is built containing: DR grade, DR label, CVD score, fused score, risk level
- The prompt is sent to BioMistral running locally via Ollama on port 11434
- BioMistral generates a written cardiovascular risk summary
- The safety filter scans the response for any clinical advice phrases
- If blocked phrases are found, the response is replaced with a safe fallback message
- A mandatory research disclaimer is appended to every response
- The final safe report is saved to MySQL and displayed on the results page
- The chatbot uses the same pipeline for follow-up Q&A

## Layer 4 — Database Layer (MySQL local port 3306)

Tables and their purpose:
- predictions: one row per image upload — stores DR grade, CVD score, risk level, timestamp
- heatmaps: stores the file path of each generated heatmap linked to a prediction
- llm_reports: stores the full text of each LLM-generated report linked to a prediction
- chat_history: stores every user question and LLM response from the chatbot

# 8. ML Pipeline Implementation Plan

## Preprocessing (ml/preprocess.py)

Border cropping:
- Many retinal images have a large black circular border
- Use OpenCV to convert to greyscale and apply a binary threshold
- Find the largest contour (the fundus circle)
- Crop the image to the bounding box of that contour

Resizing:
- Resize every cropped image to exactly 224x224 pixels

Colour conversion:
- OpenCV loads images in BGR format — convert to RGB

Normalisation:
- Apply ImageNet mean [0.485, 0.456, 0.406] and std [0.229, 0.224, 0.225]
- Required because both models were pre-trained on ImageNet

Tensor conversion:
- Convert the PIL image to a PyTorch tensor
- Add a batch dimension so shape becomes [1, 3, 224, 224]

## Model Loading (models/model_loader.py)

For ResNet-50:
- Load the ResNet-50 architecture from torchvision
- Replace the final fully connected layer with a new one outputting 5 classes
- Load saved weights from models/resnet50.pth
- Set to evaluation mode and move to MPS device

For EfficientNet-B4:
- Load the EfficientNet-B4 architecture from torchvision
- Replace the final classifier with a single output node
- Load saved weights from models/efficientnet.pth
- Set to evaluation mode and move to MPS device

Target layer identification:
- For Grad-CAM, identify the final convolutional layer of each model
- For ResNet-50 this is the last layer in layer4
- For EfficientNet-B4 this is the last convolutional block before the classifier

## Running Predictions (ml/predict.py)

ResNet-50 inference:
- Pass tensor through model in no_grad context
- Apply softmax to get probabilities for each of 5 DR grades
- Return grade index with highest probability and its probability value

EfficientNet-B4 inference:
- Pass tensor through model in no_grad context
- Apply sigmoid to the single output to get a 0 to 1 CVD risk score
- Return the scalar score value

## Fusion (ml/fusion.py)

Normalise DR grade:
- Divide by 4 to get a 0 to 1 normalised score

Apply weighted formula:
- CVD_Score = (w1 x normalised_DR) + (w2 x CVD_prediction_score)
- Default w1 = 0.4, w2 = 0.6
- Clip result to stay within 0.0 to 1.0

Assign risk level:
- Score below 0.33: Low Risk
- Score 0.33 to 0.67: Moderate Risk
- Score above 0.67: High Risk

DR label mapping:
- 0: No DR (Normal)
- 1: Mild DR
- 2: Moderate DR
- 3: Severe DR
- 4: Proliferative DR

## Grad-CAM (ml/gradcam.py)

Process:
- Use the grad-cam library GradCAM class
- Pass the model and the target layer as arguments
- Run a forward pass with the input tensor
- The library hooks into the target layer and computes gradients automatically
- A grayscale activation map is returned with values 0 to 1 per pixel
- Use show_cam_on_image to overlay the activation map on the original RGB image
- Save the final heatmap image to static/heatmaps/
- Filename should include the prediction ID for later retrieval

# 9. LLM Integration Plan

## Why Two LLMs
- BioMistral is the primary model — runs via Ollama which provides a simple local API
- MedGemma is the secondary model — runs via MLX which is optimised for Apple M3
- Having two models allows comparison of output quality in the dissertation
- If one is unavailable the other serves as fallback

## How BioMistral Works

Setup:
- Ollama runs as a background service on port 11434
- The biomistral model is pulled once using the ollama pull command
- No further setup needed — it persists between restarts

How Flask calls it:
- Flask sends an HTTP POST request to http://localhost:11434/api/generate
- The request body contains the model name and the structured prompt text
- Ollama returns a JSON response with the generated text
- Flask extracts the response text and passes it to the safety filter

## How MedGemma Works

Setup:
- MedGemma is loaded via the mlx_lm Python library
- The model downloads from Hugging Face on first use and caches locally
- No API key or internet connection needed after first download

How Flask calls it:
- The mlx_lm generate function is called directly in Python
- The structured prompt is passed as a string argument
- The function returns the generated text directly

## Prompt Design

What the prompt must contain:
- A system instruction stating this is a non-clinical research tool
- The DR grade number and label
- The CVD risk score value
- The fused risk score value
- The overall risk level (Low, Moderate, or High)
- A task instruction asking for a structured explanation
- An instruction to end with the exact disclaimer text

Why this structure:
- Grounding the prompt with specific numbers reduces hallucination
- Explicit task instruction shapes the output format
- Mandatory disclaimer at the end protects against clinical misuse

## Safety Filter Plan

What it checks:
- Scans the LLM response for blocked phrases:
  you have, you are diagnosed, you should take, prescribe,
  treatment plan, clinical advice, see a doctor immediately, medical emergency
- If any blocked phrase is found, the entire response is replaced
  with a safe fallback message
- The mandatory research disclaimer is appended to every response regardless

Why this matters:
- Demonstrates responsible AI design in the dissertation
- Addresses ethical limitations section
- Shows awareness of LLM hallucination risks

# 12. Model Training Plan

## Overview
Both models are trained independently before the Flask app is built.
Training only needs to happen once.
The saved weight files (.pth) are then loaded by Flask for inference.

## ResNet-50 Training Plan

Architecture decisions:
- Load ResNet-50 with pre-trained ImageNet weights from torchvision
- Freeze all layers in the first two residual blocks
- Keep the last two blocks trainable
- Replace the final fully connected layer with a new one outputting 5 classes
- Add Dropout (0.5) before the final layer

Dataset:
- Load APTOS 2019 using a custom PyTorch Dataset class
- Augmentation: random horizontal flip, rotation up to 15 degrees, colour jitter
- Split: 70% train, 15% validation, 15% test

Training configuration:
- Loss function: CrossEntropyLoss
- Optimiser: AdamW with learning rate 1e-4
- Learning rate scheduler: ReduceLROnPlateau or Cosine Annealing
- Device: MPS (Apple M3)
- Batch size: 32
- Early stopping: stop if validation AUC-ROC does not improve for 5 epochs
- Save best weights to models/resnet50.pth

## EfficientNet-B4 Training Plan

Architecture decisions:
- Load EfficientNet-B4 with pre-trained ImageNet weights from torchvision
- Freeze early MBConv blocks
- Keep final blocks trainable
- Replace classifier with a single output node
- Add Dropout (0.5) before the output

Dataset:
- Load ODIR-5K using a separate PyTorch Dataset class
- Extract Hypertension column from full_df.csv as the binary label
- Same augmentation and split as APTOS 2019

Training configuration:
- Loss function: BCEWithLogitsLoss
- Optimiser: AdamW with learning rate 1e-4
- Device: MPS
- Batch size: 32
- Early stopping: stop if validation AUC-ROC does not improve for 5 epochs
- Save best weights to models/efficientnet.pth

## Evaluation Plan

For each model separately and for the fused output calculate:
- AUC-ROC: area under the receiver operating characteristic curve
- F1-Score: harmonic mean of precision and recall
- Sensitivity: true positive rate
- Specificity: true negative rate

Ablation study:
- Run test set through ResNet-50 only — record all metrics
- Run test set through EfficientNet-B4 only — record all metrics
- Run test set through fused output — record all metrics
- Compare all three in a results table for the dissertation
