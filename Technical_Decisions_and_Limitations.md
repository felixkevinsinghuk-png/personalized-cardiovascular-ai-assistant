# Technical Decisions, Solutions, and Limitations Report

This document serves as a comprehensive technical record of the engineering challenges, architectural decisions, applied solutions, and outstanding limitations encountered during the development of the Retinal XAI Cardiovascular Risk Assessment system. 

It is designed to be directly referenced for the **Methodology**, **Implementation**, and **Evaluation/Limitations** chapters of the final dissertation.

---

## 1. The False Negative Problem (Clinical Safety)

### The Challenge
The core limitation of retinal imaging as a diagnostic modality is that **the retina is a proxy indicator**. While it reveals microvascular damage (e.g., from diabetes or hypertension), it cannot reveal macrovascular structural damage (e.g., coronary artery disease, valvular defects, previous stent surgeries).
*   **Result:** A patient with severe systemic heart disease could present with a perfectly healthy-looking retina, causing the AI to output a dangerously reassuring "Low Risk" score.

### Evaluated & Rejected Solutions
1.  **Asymmetric Loss Function (`pos_weight`) during Retraining:** We considered heavily penalising the ResNet-50 for false negatives during training. **Rejected** because the model already possessed a 99.45% Specificity (excellent at identifying healthy retinas). Forcing it to over-diagnose would ruin this specificity, causing massive false positives.
2.  **SMOTE (Synthetic Minority Over-sampling):** **Rejected** because you cannot synthetically generate an image of "a retina that looks normal but belongs to a sick patient" — the image itself lacks the visual biomarkers.

### Final Solutions Implemented
We solved this at the **system architecture level** rather than the model level:
1.  **Clinical Context Integration:** Added a Clinical History text box. Mistral-7B reads this free-text history and extracts a continuous **Clinical Context Score (CCS)** (0.0 - 1.0).
2.  **Updated Fusion Formula:** The fusion algorithm was rewritten to incorporate the CCS:
    `Fused Score = (0.30 × DR) + (0.45 × CVD) + (0.25 × CCS)`
3.  **Clinical Safety Multiplier:** The final fused score is multiplied by `1.25` before thresholding, systematically pushing borderline cases into the next highest risk tier.
4.  **Lowered Thresholds:** The definition of "Low Risk" was tightened by lowering the ceiling threshold from `0.33` to `0.25`.

## 2. Training the Vision-Language Model (LSTM Captioner)

### The Challenge
To provide true explainability, the LLM needed to understand *why* the CNN assigned a specific grade. However, no public, large-scale dataset exists containing paired retinal images and clinician-written reports (due to HIPAA/GDPR constraints).

### Solution: Label-to-Caption Templating
We engineered a synthetic dataset by mapping the APTOS 2019 DR grades (0-4) to clinically accurate, templated sentences (e.g., Grade 3 mapped to *"Numerous haemorrhages and hard exudates are present..."*). We then trained an Encoder (ResNet-50) and Decoder (LSTM) to translate visual features directly into these words.

### Challenge: Class Confusion & Imbalance
During Live Inference testing (v1), the LSTM suffered from class confusion on severe grades. Grade 3 and Grade 4 images were generating Grade 2 captions. This was caused by the severe class imbalance in the APTOS dataset (thousands of normal images, very few severe images).

### Solutions Implemented (Retraining v2)
1.  **WeightedRandomSampler:** We modified the PyTorch `DataLoader` to apply a 3× sampling boost to Grade 3 and Grade 4 images, forcing the model to study severe cases more frequently.
2.  **Padding-Aware Loss:** Updated `CrossEntropyLoss` with `ignore_index=0` so the model wasn't penalized/rewarded for padding tokens.
3.  **ReduceLROnPlateau Scheduler:** Added dynamic learning rate reduction when the validation loss plateaued.
4.  **Early Stopping:** Enforced an 80/20 train/val split. The system halted training at Epoch 11 (after 3 epochs of no improvement) and automatically saved the optimal weights from Epoch 8 (Val Loss: `0.0247`).

### Solution: The Safety Override (Inference Guardrail)
Even with improved training, generative AI can hallucinate. To guarantee clinical safety, we implemented a **Safety Override** in `caption_inference.py`. It uses keyword matching to infer the severity of the LSTM's generated caption. If the caption understates the severity compared to the CNN's hard DR grade, the system intercepts it and overrides it with a guaranteed-correct safe template.

## 3. Large Language Model (LLM) Selection & Multi-Agent Design

### The Challenge: LLM Hallucinations
Initial tests with generic LLMs showed a tendency to hallucinate incorrect anatomical terms or offer dangerous medical advice.

### Solution: BioMistral-7B
We migrated to **BioMistral-7B** running locally via Ollama. BioMistral is fine-tuned on PubMed data, ensuring it understands the specific medical vocabulary generated by the LSTM and maintains a professional, clinical tone.

### The Challenge: Multi-Agent System Consideration
We designed a theoretical Multi-Agent architecture where separate LLMs would handle specific tasks (DR Agent, CVD Agent, Fusion Agent, Safety Agent).

### Limitation / Decision: Rejected for Production
The Multi-Agent system was **not implemented** due to hardware and temporal constraints:
1.  **Inference Speed:** Running 4 sequential LLM calls on an M3 MacBook Air (especially with models stored on an external SSD) would push single-prediction times to 2-4 minutes.
2.  **Diminishing Returns:** The current single-agent prompt successfully synthesizes all 4 data streams (DR, CVD, Caption, History) simultaneously.
*   *Note for Dissertation:* This is documented as the primary architectural recommendation for "Future Work".

## 4. Dataset Modality Limitations

### The Challenge
Can this model process OCT (Optical Coherence Tomography) or OCTA scans?

### Limitation
**No.** The entire neural network stack (ResNet-50, EfficientNet-B4, LSTM) was trained exclusively on **Colour Fundus Photography (CFP)** (APTOS 2019, ODIR 5K). 
*   An OCT B-scan is a cross-sectional grey-scale image of retinal layers.
*   An OCTA scan is a high-contrast vascular map.
Feeding these into the system would result in catastrophic failure, as the visual feature distributions are entirely alien to the CFP-trained networks. 
*   *Note for Dissertation:* Expanding support to OCT/OCTA requires retraining on modality-specific datasets and is categorized as Future Work.

## 5. Minor Technical Bugs & Resolutions

1.  **Batch Normalization Crash (Training):**
    *   *Issue:* `ValueError: Expected more than 1 value per channel when training`. Occurred when the final training batch had exactly 1 image, causing `BatchNorm1d` to fail (cannot calculate variance of 1 item).
    *   *Solution:* Added `drop_last=True` to the PyTorch `DataLoader`.
2.  **Ollama External SSD Timeout:**
    *   *Issue:* Loading a 4GB LLM from an external SSD into Mac RAM caused standard request timeouts.
    *   *Solution:* Increased `OLLAMA_TIMEOUT` environment variables to 300 seconds.
3.  **ModuleNotFoundError (Pathing):**
    *   *Issue:* Running training scripts from the home directory caused import failures for the `training` module.
    *   *Solution:* Injected `sys.path.append(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))` into all ML scripts, making them universally executable regardless of the working directory.
